# C1：云台 1 无激光离线视觉闭环

状态：候选实现；实际测试结果以本轮报告为准。仅相机居中，不实现出光、自动打靶、
激光落点或光轴标定。用户说明红色激光笔650nm、≤1mW，来源为商家标称，非实测。
本候选没有激光端口，不引入旧F103的laser驱动或point命令。

## 范围与复用

固定OV5640观察一个红色物体；OpenMV安装于云台1。要求该物体同时在两台相机视野内，
由人工确认单目标场景，再分别完成B2授权和loop_start。
`red_frame_stats`是全局红色像素统计，不提供连通域数量；OpenMV仍选择最大红色色块。
因此single_scene_confirmed是人工前置条件，不是已经实现多目标身份关联。
不支持目标出视野后的自动搜索，也不以固定相机坐标直接计算云台误差。

```mermaid
flowchart LR
 P[合成RGB565单红块] --> R[既有red_pixel_mask/red_frame_stats]
 R --> V[既有CDC/M2/共享UART]
 V --> C[真实STM32 USART3 ISR与M2解析]
 O[简化机械模型生成OpenMV 8字节帧] --> U[真实USART2 ISR与vision_feed]
 C --> F[F1观测反馈:主视觉新鲜度及OpenMV偏差]
 U --> F
 F --> RX[既有UART RX加F1校验]
 RX --> L[FPGA有界相机居中逻辑]
 L --> B[既有B2 S1/关联ACK/心跳/STOP]
 B --> S[真实STM32安全状态机与PWM寄存器模型]
 S --> O
```

测试入口是RGB565像素，不是OV5640 DVP电气信号。Python只提供图像、人工授权输入和
显式标注的机械模型；不计算或发送PAN/TLT命令。命令由RTL生成，经逐位UART模型
进入真实C代码。OpenMV字节按8N1时长送入USART2接收寄存器/ISR模型，未模拟STM32内部
模拟采样电路；未运行真实传感器。本机OpenMV IDE 5.0.0保留，未连接、运行或写入设备。

## 新增模块与开关

- `gimbal1_visual_loop.v`：反馈CRC/会话/严格递增接收计数检查，有界交替轴小步逻辑。
- `zynq_gimbal1_loop.v`：可综合封装，复用原`zynq_vision_link`和B2；没有外部裸运动入口。
- `c1_feedback.h`及main条件分支：仅在C1_CLOSED_LOOP、C1_OBSERVATIONS和S1ACK1启用时
  回传观测，不调用arm/PID/PWM/续租。默认构建不启用新反馈。
- 原OpenMV脚本、红色识别、B2 RTL、board/safety/tracking/PID及三云台结构不改动。

PAN_SIGN、TILT_SIGN默认0，禁止loop_start成功；测试明确指定+1，仅为模型校准。
默认每步5us、死区3像素、候选窗口1450..1550us；这些不是实测机构限位或精度。
控制器依据B2已关联ACK更新的目标生成下一步，不把收到换行当成功。
每条新反馈最多产生一次、一个轴请求；两轴交替，另一轴值保留。
无积分器，不新增或调节已有PID。进入死区时停止新增位置请求，保持原B2授权及心跳；
这不是PWM关闭。显式STOP或故障才进入停机路径。

## F1反馈协议（本候选已实现）

固定55字节ASCII行（含LF），小写十六进制，CRC16-CCITT-FALSE沿用安全协议算法：

```text
F1 ssssssssssssssss ffffffff pppppppp xxxx yyyy v*cccc\n
```

| 字段 | 意义 |
| --- | --- |
| s (16hex) | 已绑定M2日志会话64位；不是运动nonce，也不是授权 |
| f (8hex) | MCU解析OpenMV后的本地接收计数，不伪称相机原始帧序号 |
| p (8hex) | MCU已接受的PL测量帧号，追踪证据用途；PL递增检查在M2接收端完成 |
| x/y (各4hex) | OpenMV有符号16位dx/dy，二补码；dx=cx-80，dy=60-cy |
| v | 仅0/1：OpenMV有效且未过期，PL完整/有目标/未过期时为1 |
| c (4hex) | 覆盖前49字节的CRC，初值FFFF、多项式1021、不反射 |

只支持gimbal0/camera0+camera1绑定，不能把F1用于云台2/3。其他设备上下文保持独立离线。
有效反馈最多20Hz；发送前TX余量至少320字节，发送55字节后为控制应答保留至少256字节。
无效完整帧不受50ms发送间隔限制；队列不足则丢弃，让FPGA反馈超时失败关闭。
原OpenMV8字节协议没有CRC/源帧号，F1的CRC只覆盖MCU到FPGA，不能证明上游未被
篡改或所有字节损坏均可检出。不会因此把这条观测链升级为安全认证通道。

115200/8N1：F1单行4.774ms、20Hz约占MCU→FPGA方向9.55%。M2在10Hz占另一方向9.72%；
双向负载不能当成同一半双工总线相加。还需计入ACK/状态/心跳，现有控制优先队列保留。

## 停机与恢复

上电/复位不发运动请求；查询、会话配置及ARM都不等于loop_start。
只有人工授权后的B2 READY、有效测量会话、单目标确认及非零方向配置才能启动。
启动后等待新反馈，不使用启动前缓存直接移动。
运行中重复启动沿被忽略，不能刷新反馈超时期限；这项约束有修复前失败、修复后通过的反例测试。

- 错CRC/串口帧错/有效性0/坐标越界/单目标条件撤销：锁定loop故障并请求B2 STOP。
- 错会话或重复/倒退计数：忽略，不产生请求、不续反馈期限；持续发生则200ms超时。
- 主视觉过期：真实C回送无效F1；OpenMV停发/坏尾帧：不产生新有效反馈，触发200ms期限。
- 目标请求超候选窗口：停止而不是裁剪后继续。没有HOME或自动搜索补救。
- MCU/FPGA串口应答丢失仍由B2关联ACK及MCU500ms独立租约处理。
- 通信恢复、有效数据恢复或再次按loop_start都不清除已锁定loop_fault。
  本候选需逻辑复位后重新发现、配置新会话、授权及启动；尚未提供免复位清故障接口。
- STOP送出不是停机证据；端到端测试检查真实C驱动的TIM4 CCER寄存器模型为0。
  PWM关闭不等于切断舵机动力，不证明实际波形或机械停稳。

## 离线测试解释

联合测试使用10MHz系统/约7.14MHz相机参考时钟，保持115200波特率；10MHz整数分频87
产生8.7us位周期，MCU线模型用8.68us。另有100MHz定向UART反馈TB，覆盖会话、重复、
CRC、缺失、故障锁定、显式启动和默认方向禁用。时钟均是仿真参数。
机械模型：两个轴相互独立、无惯性/间隙，误差=目标脉宽减软件脉宽，比例1px/us。
它用于验证闭环方向、序列及终止条件，不是实际舵机辨识，不证明真实系统稳定裕度。

原有时钟、板级I/O、跨复位epoch提供者与防回滚、实际固件身份和机械标定阻塞仍有效。
保持激光关闭不足以消除这些阻塞。本轮禁止并且未执行烧录、JTAG、真实串口、PWM或供电操作。
