## 219 位 CDC 的逐项处置

[自动审计](../tools/audit_c1_readiness.py)读取已提交的 routed CDC 报告，
要求恰好219条 CDC-15、位号0..218一一对应、每条有 Max Delay Datapath Only，
并要求两条深度2的 CDC-3。出现新类别、漏位、重位或错接时失败。
逐位字段和源文件哈希见 `report/evidence/c1-readiness/audit.json`。
这是历史实现证据复核，不是本轮重新布局布线。

| 位范围 | 字段 | 处置 |
| --- | --- | --- |
| 0..8 / 9..18 / 19..27 / 28..37 | ymax/xmax/ymin/xmin | 条件性接受邮箱结构，保留警告 |
| 38..65 / 66..93 / 94..112 | sum_y/sum_x/count | 同上 |
| 113 / 114 | target/complete | 同上 |
| 115..146 / 147..178 | capture_tick/frame_seq | 同上 |
| 179..194 / 195..210 / 211..218 | height/width/mask_version | 同上 |

源码依据：`vision_snapshot_cdc.v`仅在src_valid且src_ready时同时锁存holding和
翻转request；request经过目的域两级同步，目的状态机随后才采样holding。
在无亚稳延迟时，采样至少晚于首次捕获request两个目的时钟边沿。
目的端消费之前不回ack；ack经过源域两级同步后才允许覆盖holding。
因此数据保持覆盖整个传输和背压期；不能将219位各自打两拍替代原子邮箱。
此推理依赖源数据在源时钟有效边沿稳定、正确时序约束、无毛刺复位，
数字仿真不能证明亚稳态概率或MTBF。

当前约束仅切toggle首级D，数据路径受10ns max_delay和10ns bus_skew约束，
没有整个时钟域的false_path。历史布线总线偏斜0.726ns、余量9.274ns、219端点；
WNS +0.221ns。不能单凭skew证明绝对路径延迟，也不能把OOC余量当板级验收。
实际集成必须重跑路径报告、CDC、复位恢复/撤销、同步器布局和时钟关系审查。

新测试以现有冻结TB为基础生成219位夹具，保持原断言，覆盖源/目的半周期
7/5、3/11、11/3、5/5、5/6ns，额外相位0/2/1/3/2ns。
检查原子性、背压、丢弃、两域独立复位清空、显式恢复及holding保持。
首轮3/11因600源周期不足40次成功传输而失败；保留失败，统一增加为2400周期，
原有通过阈值不变。全部5组通过。这仍不等于所有频率或模拟亚稳态验证。

## 真实时钟与板级边界

本机厂商资料源的SHA及参考成员哈希记录在 `board-reference.json`，不上传厂商源码。
参考文件是XC7Z100的50_ov5640_udp_pc，不是当前C1已经接入的板级顶层。

| 项目 | 可确认的资料事实 | 尚不能确认的硬件事实 |
| --- | --- | --- |
| 系统振荡器 | 核心板1V1原理图标注SiT9121-100MHZ；参考XDC sys_clk_p D9、DIFF_SSTL135、10ns | 实物频率、抖动、当前C1接入哪一路；不是全板LVCMOS33 |
| 参考内部时钟 | 顶层clk_wiz输出clk_50m和clk_200m | C1尚未有完整顶层集成；不能将50MHz接入默认100MHz参数 |
| 摄像头时钟 | 参考XDC cam_pclk U22、LVCMOS33、20ns；且有CLOCK_DEDICATED_ROUTE FALSE | 真实相机配置下PCLK频率、占空比、数据建立保持及布线路径；C1的14ns仅测试参数 |
| J23 | 原透传XDC AB25 TX→PC11，AB26 RX←PC10 | 现场电压、信号完整性、本轮接线状态 |
| PC串口 | AA27 pc_rx、AA28 pc_tx，参考LVCMOS33 | 外部静默握手与复位期间线路状态 |
| 器件 | 历史JTAG确认XC7Z100系列；参考工程ffg900-2 | 实物封装、速度级 |

参考cam_pclk的非专用路由例外不可不经审查直接复制。厂商20ns与本轮14ns
都是约束声明，均不是当前摄像头的测量结果。两者必须区分。

最新C1 OOC是505个no_input_delay和138个no_output_delay，B2的155/73已不适用。
不能给全部端口填0或切除路径。必须先定义真正板级封装：

| 端口类别 | 集成动作与约束来源 |
| --- | --- |
| clk/camera_clk | 由真实输入buffer/时钟IP或PCLK驱动，声明真实主/生成时钟 |
| camera_snapshot/strobe | 与统计模块同域内部连线；若实际来自外部，必须另给发送端时序 |
| epoch/axis/pulse/config_nonce/config_session | 原子寄存器邮箱；跨域整包握手，不是各位独立同步 |
| query/authorize/command/stop/request_local/pc_quiet_ack | 同域接口或同步消抖与边沿限定；当前没有确认按钮引脚 |
| pc_rx/mcu_rx | RX同步器首级约束和异步线路分析；所有权用到的原始PC输入仍需完整顶层CDC审查 |
| reset_n/camera_reset_n | 外部复位无毛刺、异步断言与每域同步释放；邮箱局部处理不代表所有B2逻辑已完成释放同步 |
| 状态、计数、PWM软件目标 | 内部状态总线/ILA，不能当作必须分配的物理引脚 |
| UART TX/透传 | 保留映射，验证线路所有权/整帧静默；不猜同步对端output_delay |

因此本轮不改原XDC、不生成虚构板级约束。时钟资料缺口缩小，但实物和完整顶层仍阻塞。

## 跨复位 epoch：建议的可实施接口

**状态：生产提供者与 RTL 区间终点保护仍为设计方案。全 128 位数值边界已增加 ARM 预留 STOP 编号和 STOP 防回绕，见最新修复报告。**
现有`zynq_motion_s1.v`从顶层epoch读取QID，last_epoch随复位清零；重新授权
查询和STOP递增QID。历史版本只有授权全1检查；新候选已补 STOP 防回绕和授权预留，
但这不是持久化区间分配或完整历史防重放。
新epoch仅比旧值加1仍可能与上轮内部QID重叠。仿真夹具不同常量不能解决此问题。

优先方案：独立持久化分配服务 + 唯一受管命名空间 + 不重叠区间预留。
建议128位布局：namespace64 | reservation32 | offset32。此布局尚非S1线协议新增字段，
线上仍为128位QID；只是分配契约。namespace必须登记唯一，不能用随意固定值。
reservation不得回绕；offset为当前区间内消耗计数。

1. 分配端使用经确认的非易失介质，先耐掉电提交下一区间高水位，再把区间释放给PL。
   “数据库事务成功”仍需介质flush/断电行为证明；仅SQLite或文件rename不能证明防回滚。
2. 整包提交`start,end,allocation_id,valid`，PL通过同步握手锁存。重复投递不得重新装载
   已消费区间；配置端复位后也不能把旧凭证再授予新的PL启动。
3. 每次PL逻辑复位或掉电都废弃剩余区间，启动后默认invalid，等待全新区间。
   分配提交后传输前掉电可浪费区间，绝不可复用；禁止根据“未收到ACK”回收区间。
4. 所有QUERY、ARM前重新查询、STOP所用QID都必须通过统一next_qid分配点。
   在最后可用ID之前预留STOP容量；无有效区间时禁止ARM/运动，失效时依赖MCU本地租约
   停止且保持故障，不声称发送STOP就已确认停止。不得让计数越过end或回绕。
5. 备份回滚、存储克隆、设备替换或高水位损坏必须停止分配并重新登记命名空间。
   无可信防回滚服务/硬件或可审核恢复制度，仍为HARDWARE BLOCKER。
6. 恢复仅恢复发现能力，绝不恢复人工授权；旧S1SYNC/ACK/nonce全部丢弃。
   MCU随机nonce不替代请求端epoch唯一性：单纯接受MCU新鲜公告仍可被旧公告重放。

建议实施前置测试：两个并发分配请求区间无交集；提交前/后和交付前/后崩溃注入；
ACK丢失后区间不回收；PL两种复位后旧区间拒绝；每个内部QID路径边界扫描；
namespace/reservation/offset耗尽失败关闭；旧响应重放保持未授权；存储缺失/损坏/
回滚触发失效。前半部分可先做主机参考实现，最后仍需真实介质断电和供应链证明。
本轮没有把这些计划测试记成PASS，也没有更改B2协议以绕过此门槛。
