# C1 同靶核验、标定与 epoch 候选

本轮允许无动力相机观测与离线开发，不允许真实运动。板上仍为只观测封装，ARM/位置入口在硬件中禁用；未重新配置 FPGA、未烧录 MCU/相机、未发送真实运动指令。激光与舵机动力由用户确认保持断开。

## 已核对的现场事实

最新复测：两台相机画面均选中图案纸上的完整红圆。OpenMV 在 160×120 画面中回报 dx=-4、dy=31，即 cx=76、cy=29；固定 OV5640 的 640×480 质心约为 (340..341,195)。这些是各自像素坐标，不能直接相减，也不能换算为舵机角度。

这是现场人工确认只有一张指定纸靶的身份核验，不是 FPGA 多目标身份关联算法。两机相邻图案的左右关系不同，原因可能包括安装朝向、镜像和视角，尚未逐项测量；未自动修改图像镜像或控制正方向。OpenMV 的翻转配置影响读出方向，接口说明参见[官方 sensor 文档](https://docs.openmv.io/v4.5.6/library/omv.sensor.html)，当前设备 5.0.0 的实际翻转配置仍需独立读回。

两机传输统计、失败记录和范围见[本次实验报告](../report/experiments/2026-11-02-c1-target-epoch.md)。同帧字段一致不等于几何外参已标定；本地实景截图不公开。

## 标定检查代码

[分析工具](../tools/c1_calibration.py)只分析样本并输出证据缺口，不连接串口，不自动写入 RTL 符号，不授予运动权限。

- PAN 与 TLT 分别辨识，另一轴的软件目标必须固定；每轴至少三个不同脉宽目标，每个目标重复观测。
- 输入使用现有反馈语义 dx=cx-80、dy=60-cy。拟合局部误差对软件目标的斜率与交叉耦合；建议控制符号为斜率的反号。
- 响应斜率、残差和耦合容许值必须由明确的实验验收策略提供。没有默认“合格”阈值。
- 同靶身份、图像方向、独立 PWM 波形、机械允许窗口和 epoch 供应均单独检查；1500us 不代表真实机械零点。
- 合成样本即使数学拟合准确，也不能升级为实测标定。完整声明最多返回 EVIDENCE_REVIEW_REQUIRED，始终 motion_authorized=false。

[当前记录](../board/skystar_f407/gimbal1_calibration.pending.json)保持两轴样本为空、相机几何未知；云台 2、3 未连接且未标定。本次不允许运动，故不能取得新的机械响应曲线，也不会根据旧动作描述猜测方向。

复现命令（输出路径须在 D 盘）：

```text
python tools/c1_calibration.py board/skystar_f407/gimbal1_calibration.pending.json --output <D-stage>/calibration-assessment.json
```

当前预期退出 2、BLOCKED；这是对缺失标定的拒绝结果，不是程序测试失败。

## epoch 区间的离线实现

沿用已评审布局 namespace64 | reservation32 | offset32，不更改线上 S1/S1ACK1 格式，也不更改 MCU nonce、序号、500ms 租约或 200ms 部分命令超时。

[持久化参考](../tools/epoch_range_reference.py)在两份显式初始化的 SQLite 日志中保存高水位，获取固定顺序的写锁、核对状态一致，先提交两份记录，再返回整段 2^32 编号。提交后交付前中断会浪费区间；中途分裂提交使后续分配锁定，不能因 ACK 丢失回收。缺失、损坏、单份回滚或 reservation 耗尽均拒绝分配。

**这只是离线参考，不是生产 epoch 服务。** initialize 的 registration 是来源记录，不证明命名空间在所有设备中唯一。SQLite FULL 不证明实际介质断电持久性；两份日志同时回滚/克隆仍可重用区间。测试特意重现这一反例，返回 production_ready=false，绝不把重复编号判定为安全成功。

[RTL 区间分配候选](../src/rtl/epoch_qid_allocator.v)仅负责单个启动内的边界：

| 输入/输出 | 语义 |
| --- | --- |
| load、range_start/end | 同域完整区间提交；load 上升沿锁存；不是物理引脚定义 |
| take | 一个普通 QID 请求；最后一个编号保留给 STOP |
| stop_take | 消耗一个 STOP 编号并废弃区间剩余部分 |
| qid_valid / denied | 接受或拒绝的单周期事件，不能忽略 valid 使用旧 qid |
| active / stop_only | 当前区间可用、仅剩 STOP 编号 |
| fault | 非法区间、覆盖活动区间、同启动旧区间重放或模糊请求造成锁定 |

复位清除区间、结果与可用状态；同一启动只能装入高于此前 end 的新段。异步复位释放必须由未来顶层在本域同步。**复位后重放旧 grant 不能靠这个易失模块检测**，Testbench 明确保留并展示此限制，必须由持久化服务和启动代际绑定解决。

该模块尚未接入 zynq_motion_s1。现有 QUERY/ARM 前重新查询/STOP 仍由 B2 内部 qid 递增；不能仅把 start 接到 epoch 就声称 end 已覆盖所有路径。下一步应统一这些分配点，等待 qid_valid 后再构造请求，并让无有效区间时禁止 ARM/运动、超时依赖 MCU 本地租约失败关闭。保留显式人工授权，不能由 load 或查询触发使能。

## 真实供应与防回滚：仍为 HARDWARE BLOCKER

建议由 Zynq PS 或独立受管服务持久化供应区间，PL 不依赖 PC 发送运动命令。具体 PS 启动工程、可靠 NVM、原子邮箱、复位代际绑定和防回滚锚点尚未落实。STM32 内部 Flash 双页追加日志是备选，但需先正式保留扇区、证明不会被应用/备份恢复擦写、验证断电和磨损；本轮没有分配或擦写任何扇区。

注册命名空间与维护流程必须覆盖设备替换、整盘克隆、恢复备份和重刷固件。双日志不是可信硬件单调计数器。若采用硬件随机数，只能给出有条件碰撞概率与健康检测，不能声明绝不重复；不以 MCU 的随机 nonce 替代请求端 QID 新鲜性。

进入实机运动前仍需：可靠持久化/防回滚证据；全路径 QID 接入与重放测试；实际时钟、电平和 I/O；完整 CDC 签核；经授权的机械小步标定；必要的独立波形测量。本次不解除这些门槛。
