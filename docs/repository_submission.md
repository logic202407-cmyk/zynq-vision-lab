# 参赛仓库交付计划

更新日期：2026-09-24。依据 AMD 自主选题赛道指南 `master@e47e4a81c2a6a35dbd0b25dcaa4d2edef9daf643` 的 3.3.3 与 3.3.5 节；最终格式与时间仍以大赛后续正式公告为准。[来源与核对边界](sources.md)

## 仓库是正式交付物

本项目使用公开仓库 `https://github.com/logic202407-cmyk/zynq-vision-lab` 作为作品源码与复现说明的提交地址。赛事指南要求作品在 GitHub 或 Gitee 开源并使用允许再分发的协议，同时要求完整工程源码、仿真或验证结果、综合与实现报告、上板工程和实测输出、参考结果对比，以及可复现构建脚本。设计报告、大模型协作记录与可复用 Skill 也属于提交内容。

**2026-09-24 的状态：**公开仓库仅有 README、MIT 许可、项目规划、Gate 执行方案和来源清单。尚无可运行的 FPGA 工程、RTL/HLS/PS 业务源码、构建脚本、板测证据或线上 CI。因此它是已建立的交付地址，不是合格的最终工程包。

## 按 Gate 填充，而不是赛前一次性上传

| 阶段 | 应进入仓库的可公开成果 | 合并前复核 |
|---|---|---|
| Gate A | README、许可、任务与来源、公开检查工具及 CI（逐文件审查后） | 克隆后运行基础检查；公开内容与原厂/私人资料分离 |
| Gate B | 确切板卡、器件、相机和工具/IP 版本；约束来源说明 | 实物证据可复核；不公开个人信息、许可文件或未经授权照片 |
| Gate C | 最小工程的原创源文件、约束、重建脚本、构建与上板记录 | 从干净目录构建并下载；另一人复核 part、时序与日志 |
| Gate D | 可合法再分发的集成修改，或明确的原厂工程获取方式、版本、补丁与启动步骤 | 能重复视频基线；不把原厂材料误标成 MIT 原创 |
| Gate E | 接口契约、获授权测试输入、黄金参考程序、预期输出与比对脚本 | 输入来源和数据格式清楚，参考自身通过测试 |
| Gate F | 自编 PL 模块、testbench/仿真结果、综合与实现报告、板测输出和对照数据 | 每项结论指向同一提交、工具版本和原始证据 |

未采用 RTL、HLS 或 PS 中某一实现方式时，README 应写明实际架构，不为填目录伪造源码。大型位流或原始视频若不适合 Git，可通过允许公开的发布附件或数据存储提供，仓库保留获取方式、对应提交和 SHA-256；源码与构建脚本仍须可取得。

## 每次合并到 `main` 的最低检查

1. 每个任务在短分支完成，写明新增文件、实际执行的测试、失败和未验证边界；复核人确认后合并。
2. 对新增文件检查账号、令牌、报名材料、许可证、原厂工程、图片/视频授权与第三方许可；登记来源。公开仓库只接收可合法发布的内容。
3. 从新的克隆目录运行该任务的检查；保存命令、退出码和日志。CI 只能覆盖已配置的检查，不能替代 Vivado 实现和板测。
4. 回读 GitHub `main` 提交及文件；文档、报告、板测记录指向同一提交号。不要只在某个人的电脑上保留关键工程。

公开仓库的 Git 检出目录为 `zynq-vision-lab-live`。含内部交接内容的本地 scaffold 仅作参考；材料逐文件审查后再进入公开仓库，不把原始目录整体推送。

## 提交前的仓库验收

- [ ] 仓库链接可由未登录的浏览器打开；协议与第三方许可清楚。
- [ ] 指定提交或标签下，另一名队员能够从零克隆，按照 README 安装已声明的工具/依赖并重建实际采用的工程。
- [ ] 所用器件、板卡版本、时钟、引脚、相机和工具/IP 版本与板测实物一致。
- [ ] 自编源代码、仿真/验证脚本及结果、综合与实现报告、上板步骤、实测输出、参考比对都可按索引找到。
- [ ] 报告中的帧率、误差、资源、时序与原始日志和同一提交一致；未测项明确写未测。
- [ ] Skill 写明适用范围、使用方法、失效条件和实际验证；AI 协作记录只收录与工程有关的代表性过程。
- [ ] 运行一次公开内容审查、完整克隆复现和链接检查；提交后回读远程 SHA、附件/文件校验和及最终仓库地址。

负责人：队长维护 `main` 与最终地址；软件参考成员核对代码、数据和比对结果；硬件实验成员核对实物、板测与第二人复现。任何一项缺少真实证据就标为待完成，不以规划文档替代。

计划在 2026-10-19 功能冻结前让主要源码和重建方法持续进入仓库；10 月下旬完成独立复现与材料审查，保留 11 月初的上传缓冲。日期和具体上传入口以正式公告复核。
