## 1. 本轮到底增加什么

在已有“相机 → PL 颜色测量 → UDP → PC”基础上，增加“多标志对象表 → 空间关系 → 时间状态 → 可解释查询”。核心交付是确定性几何关系测量，不是把完整 RelateAnything 移植进 FPGA。

推荐功能名称：**多标志场景关系感知**。不需要为接入一个参考项目立即更换作品名称或主线。

本轮继续遵守仓库 2026-09-26 决策：无生命几何标志，输出屏显、位置测量和实验日志。不恢复舵机带动激光追随目标的早期方案；运动实验可以在视觉链路稳定后采用手动移动纸质标志。依据：[R1][R2]。

### 最终可展示的任务

桌面放红、绿、蓝三张哑光色卡，每种颜色一张。界面显示各标志测量值、关系和证据来源。用户选择“蓝色标志左侧最近的标志”，系统先筛选蓝色左侧的有效标志，再比较图像平面距离，唯一时高亮，否则显示“无匹配 / 存在歧义 / 数据无效”。移动色卡后关系变化；遮挡参考色卡后查询立即失效，历史图仅作明确标注的回看。

这一演示验证的是“识别测量对象—构建关系—执行受约束查询—解释结果”，不是通用物体识别、自由自然语言理解、真实三维关系理解或实体指向控制。

## 3. 从 RelateAnything 借鉴与舍弃的部分

| 上游思想 | 本项目采用方式 | 明确不做 |
|---|---|---|
| 图像区域作为统一输入 | 冻结对象表，让颜色统计、配置 ROI 和未来算法都能接入 | 不把它当目标检测器 |
| 目标对几何表示 | 独立实现矩形中心位移、交集、包含、距离等定点运算 | 不逐字移植 19 维编码器及其 MLP |
| 空间与语义分层 | 核心层记录几何证据，模型推断单列、可关闭 | 不把手写规则宣称为神经网络推理 |
| 时间稳定性 | 区分“测得不成立”和“没有有效观测”，增加迟滞、确认与过期 | 首轮不引入 Kalman/ByteTrack 全套跟踪 |
| 可追溯输出 | 每条关系绑定帧、对象、参数、来源和状态 | 不用接收时间近似代替同帧证据 |
| 候选对筛选 | 最多三色标志加一个配置 ROI，直接遍历有序对 | 不实现小场景不需要的学习式 PairSampler |

上游 `RelGeomEncoder` 将 19 项特征送入 MLP；其中有对数、平方根、tanh 等操作，并非现成的 FPGA 空间关系判定器。[R6] 上游 `decompose.py` 是对模型词表的空间/语义分组，而非两个独立模型；其每组每对仅取最佳关系的显示策略不直接照搬，我们允许“左侧”和“上方”同时成立。[R7]

上游模型需要图像和外部区域，本身不负责检测；现有发行推荐模型约 53.2M 参数，部署说明覆盖 CPU/GPU/浏览器，未提供本板卡验证路径。[R9] 不把“资源多”直接等同于“无法运行”，但完整移植没有本阶段的实施依据，不纳入截止前关键路径。

## 4. 目标架构与落地顺序

```text
OV5640 → 已验证的 DVP/RGB565 适配
                ↓
PL：多色掩膜 → 可旁路多数滤波 → 各色统计 → 同帧稳定快照
                                                ↓
                                     PL：定点空间关系引擎
                                                ↓
                         PS：对象有效性、关系状态、参数、日志
                                                ↓
                               PC：视频、关系、查询结果显示

同帧图像 + 同帧对象表 ──→ 可选 PC RelateAnything 实验
                              ↓
                       独立模型建议层，不覆盖几何事实
```

开发时先在 PC 上实现黄金参考与状态机，验证定义后将几何运算移到 PL，将轻量管理移到 PS。PC 承担状态管理的阶段须显示 `manager_backend=pc_reference`；只有真实 PS 程序读到正确稳定快照后才显示 `manager_backend=ps`。

不为这一功能迁移整套视频链路，不先引入 Linux、PYNQ、DPU、YOLO、全帧 DMA 或新的显示框架。PS 只读很小的统计/关系快照即可。若 10 月 20 日前 PS 路径仍不稳定，保留真实的“PL 测量/关系 + PC 管理”结果，不伪称 PS 已参与。

## 5. 模块一：三色对象测量

首版支持三种经过实拍标定、可区分的颜色，每种最多一个物理标志；颜色槽位是 `marker_id`，不是通用跟踪器产生的身份。红色沿用现有基线，绿色和蓝色阈值必须由实际相机采样确定。

每色统计 `count, sum_x, sum_y, bbox, valid`；面积下限、图像边缘接触、填充比例等可用于质量解释，但不转换成虚构的“识别概率”。同色多个物体仍会合并，必须在说明书和界面明确限制，不能承诺仅靠填充率总能检测出这一情况。

建议新增通用模块并保留 `red_*` 基线，不直接删除或大规模改写已板测路径。多色模式需明确阈值重叠时的策略，例如冲突像素不归属任一色并计数；黄金参考与 RTL 必须采用同一策略。仅启用红色且关闭新增功能时，旧结果应保持逐位一致。

3×3 去噪按颜色独立处理，保持当前“外圈不输出、输出对应窗口中心坐标”的约定。新增的二值行缓存不意味着整个原厂视频系统不使用 DDR；报告须区分新增算子存储与系统总存储。[R4]

## 6. 模块二：确定性空间关系引擎

### 6.1 几何约定

图像原点左上，x 向右，y 向下；bbox 两端包含。[R4] 核心关系使用 **bbox 几何中心**，显示中的 **掩膜像素质心** 单独保留。不能混用二者。

避免在 PL 加入质心除法：

```text
cx2 = xmin + xmax             # 二倍 bbox 中心，保留半像素精度
cy2 = ymin + ymax
left_of(A,B): cx2(B)-cx2(A) > 2*margin
above(A,B):   cy2(B)-cy2(A) > 2*margin

iw = max(0, min(xmaxA,xmaxB)-max(xminA,xminB)+1)
ih = max(0, min(ymaxA,ymaxB)-max(yminA,yminB)+1)
intersection = iw*ih
union = area_bbox_A + area_bbox_B - intersection
```

`area_bbox` 是包围框面积，不是掩膜 `count`。比较 IoU 与有理阈值 p/q 可使用 `q*intersection >= p*union`；距离比较使用二倍中心的平方距离，不求平方根。所有乘法需按范围显式扩宽。具体阈值属于配置，不能未经实拍就声称最优。

### 6.2 必做关系

| 关系 | 语义 |
|---|---|
| `left_of`, `right_of` | bbox 中心在图像平面的水平关系，带边界余量 |
| `above`, `below` | bbox 中心在图像平面的垂直关系，带边界余量 |
| `bbox_overlap` | 包围框交叠达到指定门槛，不代表物体实体接触 |
| `bbox_within_roi` | 标志 bbox 在配置 ROI 内，不宣称真实空间包含 |
| `near_2d` | 图像像素距离满足门槛，不是物理距离 |

最多三个实际标志；一个配置 ROI 可作为额外节点，来源必须标为 `configured_roi`。四节点最多 12 个非自身有序对，采用复用运算单元和小状态机即可，不需要学习式筛选。对已失效节点不输出肯定关系。

### 6.3 实现约束

帧末一次性锁存所有色通道，关系计算只读取锁存副本，不读取下一帧正在累加的寄存器。相机无反压，新增关系逻辑不得阻塞像素接收。计算过载、快照覆盖必须显式计数，不能静默丢结果。

640×480 的二倍中心范围：x 为 0…1278，y 为 0…958；二倍中心差建议统一使用至少 12 位有符号表示，乘法前显式扩宽。当前计数和求和位宽可参考已有范围，但更改分辨率须重新计算。[R4]

验收目标设为“快照就绪到关系可读的新增处理延迟不超过 1 ms”，这是待测目标而非已达到的速度。用真实时钟和硬件周期数测量；不得把此值写成相机到显示的端到端响应。

## 7. 模块三：时间状态和可解释查询

将测量状态与时间状态分开。测量为 `true / false / unknown`；时间状态为 `pending / confirmed / stale / lost`。缺测时原始结果必须 invalid，不保留旧坐标伪装当前测量。历史边可以变灰短暂显示，但不能继续驱动当前查询。

建议初始实验配置：三帧有效且连续的观测用于确认；首次缺测立即禁止当前查询；历史显示最多保留 200 ms，超过后标记 lost。帧号中断不算连续观测；参数更改或设备重启清空确认计数。三帧确认在约 30 FPS 下，从首个证据到确认额外跨越约 66.7 ms，不能被报告成无延迟。

空间边界采用迟滞，例如进入阈值 12 像素、保持阈值 8 像素，均为待调试初值。实现前必须给出边界表，不用滑动中值替代原始测量。现有七结果中值只在显示端，可带来约三个收到帧的运动显示延迟；不能从该轨迹反推 PL 真实延迟。[R5]

查询首版采用按钮/固定中文模板，不引入大语言模型解析。例：

```text
“蓝色标志左侧最近的标志”
→ 有效参考蓝色标志
→ left_of(candidate, blue)
→ 在合格候选中比较二维距离
→ 唯一解：高亮；无解/并列/过期：明确拒绝选择
```

这是受约束命令，不叫开放词汇自然语言理解。展示时必须同时给出所用帧号、参考标志、关系和距离，避免只有“智能选择成功”的结果标签。

上游的可取经验是区分低分证据与不可测，而不是它的某个演示百分比；本项目要自己测量抖动下降与延迟代价。[R8]

## 8. 模块四：最小 PS 接入

PS 目标任务仅为读取快照、执行有效性与时间状态机、管理参数和发送少量结构化日志。尽量采用匹配现有工程的最小裸机应用，不为读取统计量重做视频系统。

摄像头像素时钟与 PS/AXI 时钟可能不同。必须使用稳定快照加握手/双缓冲或合适的跨时钟方案；不能对多位 bbox 总线简单逐位同步后就视为一致。软件应能验证读取前后快照序号一致。参数在帧边界生效，附带 `config_epoch`，不可半帧切换阈值。

新增地址、时钟、复位、引脚与 SDK/Vitis 工程配置均须从真实工程读取，方案不提前指定地址或管脚。测试包括不同相位时钟、复位、连续快照、PS 读取中途更新、参数切换和过载标志。

PS 遇阻时继续保留可独立验收的 PL 核心和 PC 参考，不将代理写出的 C 文件等同于 PS 已上板运行。

## 9. 可选 RelateAnything 实验

### 9.1 接入方式

只在主线已稳定后，PC 独立环境中运行上游，输入来自同一帧的原始图像和本项目对象框，不另加 YOLO。先用最小发行模型或上游推荐模型对本机做准确性/延迟比较，再决定选用哪一个，不预先承诺实时帧率。

多色坐标约定和上游连续框坐标需要显式适配；上游 box 索引到 `marker_id` 的映射只对该次输入有效。标签不能被当成已经由模型识别出的物体类别。框内几何图形能否得到可靠开放词汇关系，需要实拍验证。[R9]

### 9.2 运行边界

每次请求携带 `session_id / measurement_frame_seq / config_epoch / image_transform_id`。队列仅保留最新一份完整输入，丢弃被更新替代的任务时记录计数，不积压延迟。模型输出过期、原图无法配对、任一端点失效或配置改变时，不更新当前场景图。

AI 层仅作独立可视化、离线比较或建议；几何规则与模型分数不能混成统一“置信度”。模型不开、运行失败或变慢，不影响核心测量与受约束查询。模型历史结果只能显示在对应历史帧上，不能贴到当前图像当成最新判断。

### 9.3 是否保留的判据

在固定、独立的测试集上记录误判、漏判、无效输出率、延迟中位数/p95、内存和初始化成本；不能只比较成功截图。只有证明增加了有用能力且不扰乱核心数据路径，才加入演示。对于“左、右、上、下”这类确定几何关系，若模型没有额外收益，就删除运行时依赖，保留文献引用和实验结论。

当前上游代码为 AGPL-3.0-only，9 月 29 日提交改变了代码许可证；模型权重仍有独立条款。[R10] 本阶段不把上游源代码或权重拷入 MIT 主仓库，不移植它的 Python 实现后重新标 MIT；独立运行也不自动消除许可义务，真正集成/分发前按实际使用方式核对。外部 PC 计算能否纳入最终参赛功能，还需对照届时本组规则，不预先承诺可计入评分。

## 10. 数据契约与兼容策略

完整候选契约见 [scene_relation_contract_v0_1.md](scene_relation_contract_v0_1.md)。重点如下。

每个对象、关系和图都绑定测量帧与配置版本；区分板端测量序号与 PC 本地显示帧号。当前 N 帧视频首包携带 N−1 结果，保留这一旧格式解释。只有匹配原始帧的结果才能进入黄金对照或模型输入。[R4]

保留 8 字节原厂头和 40 字节已有扩展的解析回归。当前字节 17 的 1/2 区分掩膜语义，不能不兼容地改成“场景图版本”。新传输需要单独的 `transport_version / schema_version / mask_version` 设计与头长识别，先写协议测试再改本地 packetizer。不要在此次功能里同时重写相机 UDP 全栈。

新增协议必须检查长度、目标数、坐标范围、序号和未知版本；同一快照的所有通道必须原子一致。多色/关系传输选择扩展首包或单独元数据包，应在看过真实 packetizer 接口和包长后通过一个单独决策冻结，不在未检查源码时编造字节偏移。

## 11. 验收：正确性、有效性、性能分开

以下均是拟定门槛，不是现有成果。

| 测试层 | 建议验收 |
|---|---|
| 旧功能回归 | 原有软件测试通过；单色旧模式的统计和版本解析不变 |
| 几何黄金参考 | 至少 10,000 组边界/随机合法目标对，RTL 与同规则 Python 逐字段一致 |
| 异常与时间序列 | 空目标、全帧、边缘、缺帧、乱序、重启、参数切换、错版本、过期输出均有预期断言 |
| 新链路同帧板测 | 累计至少 1,000 组已配对帧，逐色统计/关系与参考零差异；记录所有未配对/异常情况 |
| 实拍关系有效性 | 在预先定义、远离模糊边界的受控场景，准确率目标 ≥95%，有效输出覆盖率目标 ≥90%，同时报告未知比例 |
| 查询 | 至少 50 次人工标注试验，覆盖唯一解、无解和歧义；不得在无效/过期输入上高亮对象 |
| 连续运行 | 至少 300 秒运行记录，分开统计收到帧、显示帧、有效测量、关系更新和丢弃计数 |
| 性能 | 记录关系核周期/时间、图像端到端延迟、帧率、资源、时序，不用 GPU 论文数字替代本板数据 |
| 复现 | 干净克隆可运行软件测试；另一位成员按文档复现板测；失败项保留说明 |

比特一致性不能替代真实颜色识别准确性；测得几何结果一致，不代表色卡检测没有漏检或把背景当目标。人工标注测试与软硬件一致性测试分开。

建议四组对照：无空间滤波/有空间滤波；关系无时间状态/有时间状态；PC 几何参考/PL 几何核；可选模型关闭/开启。分别测框抖动、边翻转率、响应延迟和错误选择。不能只报告更平滑而隐去确认和显示延迟。

可交付降级版仍必须说清实际实现：单色 + 配置 ROI，或三色测量 + PC 关系。不能称为完整多目标关系硬件引擎，更不能称为已完成动态实体闭环。
