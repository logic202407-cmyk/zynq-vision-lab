# 视觉方案、硬件取舍与备赛节奏（2026-09-26）

本文记录近期讨论形成的**方案决策**，不是硬件验收或功能完成报告。当前 `report/status.json` 中视频链路、PL 核心、PS 应用和板测仍为 `planned`；实际板卡、相机与附件仍须按 Gate B 核验。此前的 [Gate 执行方案](execution_plan_2026-09-24.md) 和 [安全边界](safety.md) 继续适用。

## 1. 初赛前先交付可信的视觉作品

北航发布的本届赛事通知写明：初赛根据作品报告、视频等材料线上评审，决赛期间安排 FPGA 基础编程设计能力考核；通过测试的队伍才有决赛评奖资格。作品提交时间为 2026-11-04 18:00，决赛暂定 2026-11-20—22。[S01] 公开通知没有列出基础考核的个人/团队形式、题型、时长、软件环境和资料/AI 使用规则；不得将“现场独立写 Verilog”的具体形式写成已公布事实。

团队讨论时使用“约 4% 晋级决赛”作为**未独立核验的估计**，不是官方晋级率，也不作为作品质量或获奖概率的预测。基于初赛线上作品评审和当前工程起点，11 月 4 日前优先保证：可重复的视频输入、真正参与运算的自编 PL 模块、软件参考、板测数据、演示视频和可重建工程。考核训练不取消，但不抢占这些关键工作。

## 2. 冻结的 V1 技术问题与实现边界

拟验证的问题：在与实物匹配、已经跑通的 Zynq 视频链路上，流式颜色分割和区域矩统计能否在不缓存完整中间帧的前提下处理每个有效像素，并在受控光照、背景和遮挡条件下输出与软件黄金参考一致、误差可量化的几何标志位置？“每周期一个像素”是设计目标，须由实现后时序和实际输入条件验证，不是已达到的吞吐率。

推荐的第一版数据路径：

```text
实际相机 / 已说明来源的固定测试图
  -> 与实际板卡匹配的原厂视频基线
  -> 自编 PL：颜色掩膜、区域矩与边界统计、帧末稳定快照
  -> PS：质心除法、有效性判断、参数管理、日志与屏显组织
  -> 屏幕十字/包围框、帧号、实验记录和软件参考对比
```

- V1 限定**每种颜色最多一个标志**。PL 对掩膜像素累加 `area`、`sum_x`、`sum_y`、`xmin/xmax/ymin/ymax`；无目标输出明确的 invalid。PS 在稳定的同一帧快照上计算 `sum_x/area`、`sum_y/area`，并记录质量指标。寄存器位宽、溢出策略和快照协议待实际分辨率与接口确定后计算、冻结。
- 小尺度二值去噪可作为可旁路的后续功能，不能阻塞第一个单色统计模块。先做固定输入的软件参考、边界/空场景/复位/有效信号仿真，再接实时视频。AMD 颜色检测案例和相关 FPGA 视觉论文只说明技术路线可参考，不证明本板卡已实现。[S14][S16]
- 首轮不做 YOLO、Hough 圆检测、完整连通域标记或通用多目标跟踪。V2 如有余力扩展为 2—3 个**颜色可区分**标志；两个同色目标会使整体矩质心失真，必须声明不支持。同色多目标只有在 V2 稳定且确有实验需求时，才评估流式连通域方法。[S17]
- 用实际相机拍摄候选哑光色标，在不同光照和背景下比较 RGB 通道比例、YCbCr 色度阈值和 HSV 阈值的误检、漏检及定点实现成本；未采样前不指定颜色、阈值或相机像素格式。输入究竟是原厂 `VSYNC/HREF/DE` 类同步还是 AXI4-Stream，也要以选定工程为准；不能提前把所有原厂示例统一描述为 AXI4-Stream。若以后采用 AXI4-Stream Video，再按 AMD 协议处理 `TUSER` 帧首、`TLAST` 行末及 `READY/VALID` 握手。[S15]

创新叙述应落在可解释的流式统计、跨帧一致的结果快照、相同定点规则下的软硬件对照、干扰实验与可复现证据，而不是把“颜色阈值”本身称为新算法。不同输入源、延迟边界和测量条件必须写清。

## 3. 采购与可选实验装置

**现在不采购舵机或激光笔。**先核对用户实物上的 SoC 完整料号、底板/核心板版本、相机接口与型号，再确认电源、下载器、串口线、显示器及视频线缆；匹配相机的选择依赖这些实物证据。可先准备哑光纸质色标、固定支架、可重复照明条件。原厂资料中存在多个器件与相机示例，只能作为候选基线，不能证明用户手中的组合适配。

移动实验按需求分支，不是 V1 前置条件：

| 分支 | 何时考虑 | 边界 |
|---|---|---|
| 手动滑轨或单舵机移动纸质标志 | 固定相机的 V1 测量已经稳定，需要可重复的目标运动 | 优先记录实际位移/角度与时间，仍只测无生命纸质标志 |
| STM32 控舵机，Zynq PS 与 STM32 通信 | 确认 PS 串口可用且运动实验确有价值后 | 可先由 STM32 按预设轨迹运动并回传状态；PS 下发运动命令是后续独立验证项 |
| 双轴相机云台 | V2 稳定并需要受控相机运动干扰实验后 | 不与目标运动、背景变化同时引入首轮联调 |
| 光学指示 | 另行安全审核且确有展示价值时 | 首选屏显；普通漫射 LED 可表达“检测有效”。不安排舵机带动激光笔追随目标 |

若未来使用 STM32，架构候选为“PL 视觉测量 → PS 记录/串口 ↔ STM32 → 实验台舵机”，**不是已接线或已跑通的系统**。先确认实际 PS 串口引脚和双方逻辑电平，不照搬其他板卡接线；舵机由符合其规格的独立电源供电、与控制器共地，不能从 FPGA/MCU IO 引脚取电。通信至少定义命令/状态、序号、确认与超时，运动记录与视频帧号的对齐方式需实测。具体 STM32、舵机、支架和电源型号均尚未选定。实体光学装置必须另经指导教师和场地负责人审核器件类别、光路、终止屏和独立停机；未经审核不采购或启用发射装置。[S11]

## 4. 初赛前每周一次的 Verilog 练习

用户当前 Verilog 基础接近零。原规划中的“每天 30—45 分钟共同训练”在本阶段由本决策**替代**：到 11 月 4 日，以项目开发为主，每周安排一次约 90 分钟基础练习；每次独立写一个小模块、testbench，跑仿真并解释波形，练后可用 AI 复盘。板卡未齐时也能做仿真，但仿真通过不等于上板通过。

| 周次/主题 | 与项目相连的独立练习 | 最低验收 |
|---|---|---|
| 1：组合逻辑 | 像素阈值判定或 2:1 选择器 | 自己写模块、正常/边界输入测试 |
| 2：时序与计数 | 带复位/使能的计数器 | 复位、暂停、连续计数波形正确 |
| 3：有效信号 | 像素 `valid` 延迟与统计使能 | 空拍不计数，数据和有效信号对齐 |
| 4：小状态机 | 帧开始、统计、帧末快照的简化模型 | 状态转换和异常输入测试 |
| 提交前 | 限时独立重写一个学过的模块 | 不依赖 AI 完成，随后复盘错误 |

如周历与实际工程阻塞冲突，可压缩练习但应保留每周一次的独立现写现测；不为练习牺牲板测、报告和提交缓冲。若初赛入围决赛，再根据组委会公布的考核细则提升练习频率，做定时模拟和独立讲解。PS—STM32 通信或 HLS 路线不能替代 FPGA 基础能力考核准备。

## 5. 下一项可执行工作与证据门

1. 组内盘点实际板卡、核心板/底板、相机、线缆和电源；实物照片可先私下核对，不必为公开仓库提前上传。完善 `board/hardware_inventory.md` 时仍区分“在手已测试 / 在手未测试 / 不在手 / 待确认”。
2. Gate B 有实物依据后选择匹配原厂最小工程；依次完成最小上板、视频基线、数据契约、软件参考及首个自编 PL 模块。暂不买实验运动机构来代替 Gate B—F。
3. 每个成果按“已规划 → 已实现 → 仿真通过 → 实现/时序验证 → 板测通过 → 他人复现”逐级记录；本文件新增的方案本身不提升任何状态。
