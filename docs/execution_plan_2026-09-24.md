## Gate 顺序与任务卡

### Gate A — 仓库与项目基础

**主责：**队长／工程集成；**复核：**另一名队员。

1. 核对目标 GitHub 仓库的真实地址、可见性、默认分支和提交，保存本地 `remote` 与提交号。2026-09-24 已建立公开仓库；首次规划提交为 `1b491dcaaae2c9eaab7f6b0e3fb81a4a101bed3a`，后续提交以 GitHub `main` 实际回读为准。
2. 审查待公开文件：不得含个人报名资料、令牌、许可证文件、原厂工程、未经授权的图片或大型生成文件。
3. 运行 `python tools/check_repository.py` 与 `python -m unittest discover -s tests -v`，保留命令、时间、退出码和输出摘要。
4. 推送规划与执行方案后回读远程文件和提交；再单独检查 GitHub Actions 结果。线上 CI 未运行时写“未验证”。

**通过条件：**目标仓库与 `main` 提交可回读，本地基础检查通过，公开内容已审查。Gate A 只证明仓库基础可用。

赛事提交时，该仓库还必须包含完整工程与复现证据；各 Gate 的可公开成果随开发入库，最终按[参赛仓库交付计划](repository_submission.md)逐项验收。当前只有规划文件，不是可提交的工程包。

### Gate B — 实物、相机与工具链身份

**主责：**硬件实验成员；**复核：**队长。队长负责记录工具链证据。

1. 拍用户实际底板和核心板正反面，逐字记录 SoC 封装丝印、底板／核心板版本；照片先在组内核对，公开前另行脱敏与确认授权。
2. 记录实际摄像头型号、接口与供电要求，以及电源、下载器、串口、存储卡、显示器的在手和测试状态。
3. 将实物标识与同一原厂资料包中的工程 part、原理图和约束来源逐项对应，发现冲突先停止选型。
4. 记录 Vivado/Vitis 版本、目标 part 查询结果、许可状态及最小工程所用 IP 版本。能报告版本不等于能生成位流。

**输出：**本地 `board/hardware_inventory.md`、`build/toolchain_manifest.md` 与未公开的实物证据索引；公开前另行审查。

**通过条件：**实际 part、板卡版本、相机和所需附件都有可复核证据，工具能找到目标器件。缺少实物时保持 Gate B 未通过；不创建器件专属工程或 XDC。

### Gate C — 最小工程重建与上板

**前置：**Gate B 已通过。**主责：**队长／PL；**复核：**第二名队员。

选取与实际 part、板卡版本一致的原厂最小示例，记录来源和许可。在隔离的英文路径构建，依次保存综合、实现、时序、位流生成、下载及可观察输出。第二名队员从干净目录按记录重建。失败也记录原始报错、单项修改和重试结果。

**通过条件：**正确器件的位流可重复生成、下载和运行；`build/toolchain_manifest.md` 与板级日志能复核全过程。

### Gate D — 原厂视频基线

**前置：**Gate C 与实际摄像头匹配。**主责：**队长／PL；**复核：**硬件实验成员。

先原样重建匹配的相机与显示工程，确认画面确实来自当前相机。记录像素格式、分辨率、启动步骤、连续 5 分钟运行和重复启动结果；帧率若无法测量，明确写“未测”。原厂代码的许可未澄清前只在本地使用，并在公开仓库记录来源与重建步骤。

### Gate E — 数据契约与软件黄金参考

**前置：**真实视频格式明确。**主责：**软件参考／PS 成员；**复核：**队长。

冻结 `src/interface_contract.md` 的像素格式、坐标、帧号、valid、结果更新和一致性读取；制作无目标、居中、贴边、多种可区分靶、相似背景、部分遮挡六类自制或获授权输入。先定义预期输出和比较规则，再实现并测试软件参考。数据来源和失败样例记录在 `data/test_manifest.md`。

### Gate F — 第一个自编 PL 模块

**前置：**Gate E 有可执行参考，Gate D 提供可信链路。**主责：**队长／PL；**复核：**软件参考成员。

从一个像素算子或统计模块开始：参考行为 → 能检出错误的测试 → 最小 RTL/HLS 实现 → 仿真 → 综合/实现/时序 → 板级集成 → 同输入对比 → 第二人复现。逐级更新证据状态；仿真通过不写成板测通过。

## 三人本周交付与检查点

| 角色 | 最近交付 | 交接给下一角色的条件 |
|---|---|---|
| 队长／PL 与集成 | Gate A 远程与测试记录；Gate B 工具 part 查询方案；实物到场后最小工程选择 | 芯片完整料号与工程目标一致，来源和版本可追溯 |

| 硬件实验／复现 | 实物和附件盘点、照片索引、供电与接口资料、Gate C 复现表 | 实物证据可供队长核对，公开素材另行审核 |

三人会议需为每项填写姓名、复核人、预计完成日和可投入时段；公开仓库不保存报名个人信息。报名系统审核状态由队长在私人记录中跟进，不作为 FPGA 工程 Gate 的替代证据。
