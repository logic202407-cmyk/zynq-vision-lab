队友需要的代码在本分支；技术日志和两台电脑回执已实际入库，见[证据索引](../report/evidence/two-pc-handoff-20261104/README.md)。精确 BIT/LTX、STM32 BIN/AXF/HEX/MAP、回滚备份和原始电脑2结果包通过本仓库 [handoff-20261104 Release](https://github.com/logic202407-cmyk/zynq-vision-lab/releases/tag/handoff-20261104) 下载。不是要求队友去找某台电脑的本地文件。

### 尚未证明什么

- 没有云台误差收敛曲线、可靠的机械方向/中心/安装偏置标定。
- 没有激光实际亮灭、命中纸靶、丢靶关闭、实机 STOP 后关闭的完整证据。
- F1在电脑日志可见，不等于每条都被 FPGA 的某个视觉闭环模块接收或控制采用。
- 当前控制位流是 **FPGA发 ARM/AUTO/心跳/STOP，STM32运行本地OpenMV反馈PID**；不是已完成 OV5640 给三套云台分配红蓝黄目标的系统。
- 一块 STM32 接三套云台与三块 OpenMV 是最终拓扑；目前只连接一套。先完成这一套，三套目标分配、串口扩展、六路PWM分配均未验收。
- 时序 WNS/WHS通过不等于整板signoff；2处视频CDC-10 Critical和180处邮箱CDC-15警告仍在。

## 已上传的交付物怎么用

1. 先阅读本页、[台架记录](../report/skystar_team_port_bench.md)和[机器可读状态](../report/status.json)。
2. 克隆本分支。`src/prototype/skystar_openmv/stm32_skystar_tracking` 是 F407应用；`src/rtl/c1_control_link.v`、`zynq_motion_s1.v`、`zynq_vision_link.v` 是本轮控制入口修改。
3. `tools/handoff_pc2/` 提供实际可复制的被动采集程序及其 `vendor_udp.py` 依赖、90秒/300秒 RAM观测脚本。先读同目录README；没有任何脚本应随克隆自动运行。
4. Release内 `c1-control-artifacts.zip` 是精确BIT/LTX和控制脚本；`stm32-team-artifacts.zip` 是固件与调试产物；`pc2-original-results.zip` 是五个原始结果包；`stm32-backup-evidence.zip` 是已有备份和完整读回。用上传的 `SHA256SUMS.txt` 校验，解压后继续核对各包清单。
5. 证据目录中的 `.py.txt`、`.tcl.txt`、`.md.txt` 是**历史快照，不是新操作指令**。其中包含已失败程序、已被后续恢复取代的下载说明和旧路径；不要批量执行。
6. 原始Flash备份不是默认“推荐固件”；必须按 manifest 中的来源、长度和哈希区分旧镜像、擦空状态与成功读回。不得将512KiB整片备份当成允许 mass erase 的授权。

VIO UUID为 `026FEEEA049D50A0ADB93761986F1093`；新旧设计UUID/LTX相同，不能只凭UUID判断加载了控制位流，必须核对USR_ACCESS。

最后成功会话（**历史证据，不能跨重启直接复用**）：

```text
qid=e4d4ef4a1f78430d93f1f7261a5efbd9
sid=00065f6106a11698
nonce=4c74598e6eb00a38
S1SYNC e4d4ef4a1f78430d93f1f7261a5efbd9 S1ACK1 4c74598e6eb00a38 stopped boot 1500 1500 0 0 0*5761
V2A 4c74598e6eb00a38 00065f6106a11698*e5c9
F1 00065f6106a11698 00000001 00016b4e 0027 0011 1*228d
```

CRC计算为 `binascii.crc_hqx(body.encode('ascii'), 0xffff)`，body不含星号、CRC和换行。F1字段依次是会话、OpenMV帧序号、主相机测量序号、有符号16位dx/dy、有效位；第三个数值字段**不是帧龄**。主相机序号可能重复，OpenMV序号受20Hz反馈限速出现步长2–4，不能称为无丢包。

历史VIO状态：query后 `00000053`，bind后 `000000d3`，控制输出 `02`。低4位为状态；bit4为owner、bit5为fault、bit6为stop_confirmed、bit7为session_active、bits9:8为PWM mask。不要从状态码单独推导光笔实物亮灭。

## 次日顺序：先观测，再单独决定实测

1. 明确解除暂停及当轮操作范围。仅继续读日志不等于允许ARM/AUTO/烧写；最新禁止要求优先。
2. 电脑2检查供电、靶板、实际串口、网络、hw_server和采集进程。复用原服务；不要第二路JTAG，不要顺手重启服务。
3. 保存当前状态和最后日志。若采集已结束，先确认COM/UDP释放，再启动上传的被动采集程序，记录新目录和起始时间。保留旧finished证据，记录空档。
4. PC1只读检查设备身份、DONE/EOS、USR_ACCESS和LTX；若发现未配置或指纹变化，先查电源/重启记录，不自动重复下载。
5. 如需新query/bind，在已确认停止和输出关闭条件下生成新的qid/sid，核验每条原始S1SYNC/V2A CRC及nonce；绑定成功不等于有观测。
6. OpenMV IDE仅RAM运行已上传的观测脚本，记录开始/结束时间。90秒版容易短于人工回传加远端JTAG连接耗时，300秒版用于减少时间窗错配，**只延长观测，不延长运动授权**。300秒版已传输并读回校验，但没有已完成运行的证据。不要保存为相机Flash main.py。
7. 独立验证当前会话持续flag=1、正确CRC、更新的序号及正在增长的日志。历史ZIP证明旧窗口，不足以放行新动作。脚本结束的flag=0必须记录。
8. 到此仍是观测链。需要重新得到明确实测范围并落实现场条件后，才考虑运动。当前版本激光在AUTO+有效目标时可能立即点亮，**并不等待中心误差收敛**。
9. 实测时分别收集：ARM及AUTO相关S1ACK CRC/nonce/seq、连续F1误差、S1STAT状态、视频/现场云台与光斑表现、STOP回执、PWM禁用与实际停止/熄灭。缺任一项就明确记录缺项，不写“闭环完成”。

## 失败记录与避免重复踩坑

| 现象 | 已知原因/应对边界 |
|---|---|
| USB下载器曾消失、cables=0 | 查Present和设备错误码；USB存在不保证FPGA配置完成，不靠历史截图判断在线。 |
| DONE/EOS=0 | 曾明确未配置；错误位0不足以确定失败原因。后续本地XSDB下载恢复；再后续控制BIT临时下载成功。 |
| capture.py WinError5 | 原status.tmp替换status.json失败；capture-v2改为编号状态文件。 |
| ClearCommError/串口拒绝访问 | USB重新枚举、端口改变时曾退出；确认旧进程退出、实际COM号后才重启采集。 |
| 当前镜像和历史AXF不一致 | 不得继续用旧符号解释RAM结构；历史SWD帧数解释已撤回。现在用确切候选BIN及对应MAP/AXF。 |
| STM32首扇区擦除返回超时 | 实际首16KiB已全FF，后续扇区保留；官方DFP ProgramPage恢复13页成功。原因未彻底证实，禁止为了复现再擦一次。 |
| 电脑2没有ARMCC/Vivado | 不重复要求电脑2执行不存在的工具。构建和VIO由PC1负责；电脑2只提供hw_server和采集/现场操作。 |
| 3121间歇超时 | TCF目录列举和精确读取都可能失败；成功TCP握手不保证后续读文件稳定。不要无限重试或自动重启服务。 |
| TCP1534不通 | UDP发现口，不作为TCP故障判据。 |
| 远程VIO读回8–29秒 | 原脚本5秒等待不是动作硬上限；一次连接也会消耗一分钟左右。不要承诺5秒精确运动。 |
| ARM前Python SRE module mismatch | Vivado设置的PYTHONHOME污染Python3.12；外部Python使用 `-I`。隔离导入验证通过，随后缺新鲜F1，未完成运动验证。 |
| 路径编码问题 | Tcl和跨shell管道优先ASCII工具路径；不要使用已乱码的用户目录。 |

FPGA有30秒授权期限、STM32有独立租约与观测保护；这些设计和离线测试不能替代硬件测量。`run-live-once.tcl` 等仅是曾准备的实测入口，**不是已上板验证的标准操作流程**。最后两次尝试分别在等待观测和Python检查阶段终止，不能从日志打印出的Tcl源代码中出现ARM/AUTO就认定命令已执行。

## 离线复现与交付验收

```powershell
python tools/check_repository.py
python -m unittest discover -s tests -v
```

这些只检验仓库基础。历史专项证据包括默认C固件35238断言、团队固件11案例、RTL/实际C耦合正常AUTO与错误分支、OpenMV兼容性6案例；详见已上传对应result与日志。本轮发布时的检查另存 `publication-validation.txt`，不能替换历史原始记录。

ARM Compiler、Vivado、Keil DFP是工具依赖，许可证和安装包不上传。DFP版本2.17.1及所用FLM/PDSC来源哈希见已上传provenance；需要重新构建/重新编程后端时通过官方安装获得依赖。已生成的精确可用固件和BIT作为Release附件提供，普通续接无需重新构建或重新下载硬件。

Release里的 `historical-*` 保留原实现以供审查；含旧路径和旧采集目录，不是即插即用入口。尤其 `run-live-once.tcl` 仍依赖当时PC1 Python与实时检查脚本，不能直接在新电脑原样执行。`control.tcl` 的query/bind只依赖同包LTX、UUID及Vivado，但其run分支仍有上述远程时序问题。先读状态、校验输入和修改当轮配置，不能为了消除报错删除身份/CRC/新鲜度检查。

不要编辑已归档证据来让数值“通过”。新的实验新建时间戳目录，记录输入固件哈希、现场条件、命令、原始日志、结果和不确定性，再更新交接结论。
