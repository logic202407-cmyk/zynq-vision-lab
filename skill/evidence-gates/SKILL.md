# FPGA 开发证据分级与复核工作流（候选）

状态：原创整理的候选流程；尚未在本项目或其他板卡上验证，不得作为已验证的参赛技能包提交。

## 适用范围

将算法描述、模型生成代码、仿真、综合、实现、上板与独立复现分开记录。适用于 FPGA 项目的证据组织，不承担引脚、时序或功能正确性的自动保证。

## 输入

需求与接口说明；待审查提交号；实际工具版本；测试输入；仿真/综合/实现日志；板测记录；第三方依赖及来源。

## 输出

每项需求对应一条状态记录：claim、evidence_path、commit、tool_version、input_id、status、known_limit、reviewer。

status 只允许以下含义：

| 状态 | 含义 | 不代表什么 |
|---|---|---|
| planned | 只有设计或任务说明 | 不代表已编写 |
| implemented | 已有代码/配置 | 不代表测试通过 |
| simulated | 在记录的测试条件下仿真符合预期 | 不代表时序或板测通过 |
| implemented_on_device | 已完成目标器件的综合与实现，报告已检查 | 不代表真实外围接口正常 |
| board_verified | 指定实物、输入和版本通过记录的板测 | 不代表所有环境和板卡都支持 |
| reproduced | 另一人按说明重建并重复指定结果 | 不代表无限泛化 |

## 复核步骤

1. 读取需求并确定该结论需要哪一类证据。
2. 确认证据来自被审查的提交、工具配置和输入，而非旧版截图。
3. 从完整日志中检查失败、警告、跳过项目和计时口径；不能只看最后一句“success”。
4. 检查黄金参考是否独立、输入布局是否一致、测试是否能发现已知错误。
5. 对板级结论检查是否存在运行记录及接线/模式/启动条件。
6. 填写仍未覆盖的边界；未运行的检验明确写“未验证”。
7. 复核人确认后提升状态，不跨级推断。

## 失败条件

缺少实际日志；版本不对应；只有模型自报成功；把 HLS 估计代替布局布线结果；把显示配置值当实测帧率；把软件处理录像说成实时摄像头；没有定义延迟起止点；无法判断第三方代码使用范围。

遇到这些情况，应降低结论等级并补证据，而不是调整报告措辞掩盖缺口。

## 将来怎样验证此流程

选两个独立模块及一个完整链路，安排非作者按流程审核；保留至少一个被发现的版本错配或不充分结论案例，记录修正结果。若声称可跨板复用，需另有跨板试用记录。完成前保持“候选”标签。
