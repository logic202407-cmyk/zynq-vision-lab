# OpenMV H7 Plus R1 本地修正版 R6

在 OpenMV IDE 中打开本目录的 `main.py`。文件已经修改后，应选择“从磁盘重新载入”，或关闭旧标签再重新打开；不要用旧编辑器缓存覆盖修正版。运行后终端第一行应包含 `H7 Plus R1 tracking R6`，接着打印 `RED_THRESHOLD: (0, 100, 12, 41, -3, 52)`。

本次修复：旧文件的 `draw_text()` 只捕获 `TypeError`，但当前相机在解析 `draw_string((x, y), text, ...)` 时抛出 `ValueError: requested length 3 but object has length 2`。R5 同时处理这两种异常，并切换为 `draw_string(x, y, text, ...)`。修复前在模拟当前接口的两项测试中复现相同错误；修复后 6 项兼容测试全部通过。

R5 修复时沿用的是报错文件里的 `(32, 43, 13, 51, 4, 52)`，它与用户实际能正常识别的 R4 版本不一致。用户确认后，R6 已恢复 `(0, 100, 12, 41, -3, 52)`，保留 R5 绘图修复。识别筛选条件、160×120 分辨率、UART3/P4 115200、原 8 字节协议及云台 PID 不变。阈值编辑器的预览不会自动修改运行中的脚本。

相机端负责识别和发送坐标；云台及 PB0 激光联动由 [F103 工程](../README.md) 控制。F103 v4 现已允许激光联动，并在 STM32 侧加入 500mm 瞄准偏移；相机仍输出原始 dx/dy。

R6 已在 IDE 实际运行，识别、串口跟踪和光点收敛已经现场确认；仍未覆盖相机盘的启动脚本。检查时 `F:/main.py` 仍是一份灰度测量旧脚本；在 IDE 中验证 R6 正常后，需要通过 IDE 保存为相机 `main.py`，才能在相机重启后运行这份追踪代码。

可运行 `python openmv/test_compat.py` 复查六项绘图、色块接口及协议兼容测试。历史错误与修正见 [进度记录](../PROGRESS.md)。
