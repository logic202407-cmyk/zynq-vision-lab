本记录属于已有 STM32/OpenMV 原型分支。本次输入为相互分开的静止红色目标，输出为目标框、两轴位置偏差和顺序锁定状态。

## 当前行为

1. 将首次识别到的红色目标按屏幕中心横坐标从小到大排列，形成一轮。
2. 对准当前目标，两轴误差均在 ±5 像素内连续保持 200ms，进入停留阶段。
3. 持续跟踪并停留 2 秒后切换下一目标；期间超出容差或丢失目标会清零计时。
4. 切换时发送 100ms 的丢失状态帧，供现有 STM32 程序复位目标相关的 PID 和滤波状态。
5. 最后一个目标完成后保持当前位置；重新运行脚本开始下一轮。

绿框表示所有检测到的目标，红框表示当前目标；`STABLE` 表示稳定计时，`HOLD` 表示停留计时，`DONE` 表示一轮完成。

`HOLD_MS = 2000` 为停留 2 秒，改为 `1000` 可停留 1 秒。沿用 160×120 分辨率、UART3 115200 和原有 8 字节串口帧格式。

串口帧依次为 `AA FF dx_lo dx_hi dy_lo dy_hi flag EE`，偏差为有符号小端 16 位整数，`dx = cx - 80`、`dy = 60 - cy`。`flag=1` 表示当前目标有效，`flag=0` 表示等待、丢失、切换或完成。本分支的 STM32 接收端在 `flag=0` 时复位 PID 与滤波状态并保持舵机位置；后续独立 P0 分支采用另外的 26 字节协议，接入时需按各分支接口核对。

颜色阈值沿用本地第一版的 `(7, 49, 13, 45, 8, 33)`，须与实际照明核对。将 `main.py` 载入 OpenMV IDE 运行，依赖板端 `sensor`、`image`、`time`、`ustruct` 和 `pyb` 模块；主机检查仅依赖 Python 标准库，不连接设备。

## LOST 修复与验证

先前逻辑依赖旧坐标和 30 像素匹配半径。云台转动导致坐标变化后，可能一直匹配失败并发送 `flag=0`，使 STM32 保持不动，也可能错误选择靠近旧坐标的相邻目标。

现在全部目标可见时按整组左右顺序重新关联，更新真实位置并保留当前锁定进度；部分目标不可见时保留位置匹配和等待逻辑。新增检查覆盖大幅坐标变化、丢失后完整目标重新出现、相邻目标混淆，以及恢复后的有效串口帧。

```text
python -B -m unittest discover -s tests -p "test_openmv_sequence.py" -v
```
