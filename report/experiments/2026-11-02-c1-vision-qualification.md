## 查到的问题与实际修复

1. PL 原始统计把完整帧内任意红像素标为目标有效，且合并所有红区域。保留这份测量契约，不用滤掉原始日志掩盖跳变；在 STM32 的 F1 生成前增加独立控制质量检查。
2. OpenMV 原来选最大合格红 blob，不能把最大等同于指定目标。候选现在拒绝多个合格区域、贴边和几何异常，并要求三帧稳定取得；丢失后重新计数。该计数不恢复 FPGA/MCU 授权。
3. 实测 RAM 的 LAB 与仓库默认不同。没有静默更改仓库默认；诊断同时比较两个显式配置，检测都在绘图前完成，避免叠加像素污染第二个结果。
4. ARMCC 大写 Warning 漏计的问题修复为不区分大小写的诊断拒绝；main.c 用 #else 隔开 S1ACK1 与旧遥测分支，移除已知不可达代码。两个实际 ARM 配置都重新编译为零错误/零警告。

新增质量函数不写 PWM、不使能或续租。它输出无效 F1，让现有 FPGA 相机居中状态机请求 S1 STOP；原关联 ACK、500ms MCU 本地租约、200ms 部分命令保护、公共双路 PWM 使能、三云台上下文和原 UART/红色 RTL 全部保留。

详见[接口与局限](../../docs/c1_vision_qualification.md)。目前只有云台 1；另两套不因软件上下文存在就算硬件接入。

## 失败与修正

- 首次 primary_edge 用 STOP 之后的观测槽原因码断言，因 STOP 轮换 nonce 并清空观测而失败。保留失败结果与线日志；新增实际 C 原因转换记录：先观测到质量码 3，再独立检查关断和禁止自动恢复，未删除测试或放松关闭断言。
- 诊断生成器混用了 R 别名 __file__ 和解析后的 D 物理路径，生成元数据失败；统一 resolve 后重试通过。首次脚本生成不等于执行，无硬件动作。
- IDE 打开命令产生额外未连接实例，窗口输入保护拒绝歧义选择。保留正常连接实例、关闭本轮额外诊断窗口；补充 getter 运行没有完成，不伪造读数。
- 复杂内联 Python 的引号命令失败后改为独立文件/补丁。失败截图不能当作新的 UI 状态；现场图片不公开。
