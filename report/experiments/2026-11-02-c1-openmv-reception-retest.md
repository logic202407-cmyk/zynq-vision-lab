# C1 OpenMV 接收同步复测和 KEY 锁定

此前两次采样的 0 帧结果与 OpenMV 的实际发送时段没有被可靠地同步，不能据此判断 P4→PA3 通信断开。用户确认信号和共地接线正确，并确认没有按 WKUP／KEY。

在用户确认舵机动力和激光断开后，使用 OpenMV IDE 5.0.0 的有限 RAM 程序发送协议内固定无目标帧。独立 SWD 只读采样 1500 次：PA3 观察到低电平 338 次，USART2 接收队列头和尾分别观察到 234、232 个不同位置；GPIO PA3 复用 AF7、USART2 BRR=139、CR1=8228。此采样只表明活动，不是 115200 波形质量或误码率测试。

随后运行仓库默认颜色阈值的 90 秒视觉 RAM 诊断，MCU 的 OpenMV 观测帧计数从 19850 增至 21643。一次 SRAM 接收环形缓冲快照找到 32 个完整视觉帧，全部 flag=1，示例 dx=29、dy=25；另一次 MCU 观测状态读数为 dx=29、dy=24、valid=1、软件 PWM=0。环形缓冲采样可能与运行中写入竞争，不是完整串流统计。

OpenMV 画面中的默认颜色阈值只框住红圆的一部分，故上述坐标代表当前阈值的检测区域，不代表准确的红圆中心，也不能证明跨相机目标身份或机械对准。两条摄像头数据的端到端关联和 F1 尚未在本次同步复测中通过。

安全状态保持 FAULT/KEY，用户表示没有按按键。随后 PA0/WKUP 500 次只读采样均为低，且 TIM4 CCER=0；未捕捉到引发锁定的瞬间，不能确定原因。现有固件会对采到的 PA0 高电平触发 KEY 锁定，STOP 不会清除故障。本轮保留锁定，未烧录、复位、重新授权、开启 PWM 或运动。串口原始数据、现场图和测试脚本仅留 D 盘。

追加 5000 次 PA0 只读采样也均为低，状态仍为 FAULT/KEY、CCER=0。采样存在间隔，不能排除未捕获的短暂高电平，也不证明故障源已消除。

实物确认了 OpenMV→STM32 有效帧接收；后续仍需查清 KEY 触发、固定适合场景的识别阈值及完成测量会话/F1 测试。现有万用表不能验证串口或 PWM 的实际波形，epoch、约束和机械标定仍是进入自动运动前的缺口。
