# C1 实机安全固件与图像通信恢复

源码基线：`91ff049041f9e094a34a53e73f98d46a9b0281bf`。本轮用户要求推进实机全过程；经明确确认激光供电物理断开、随后舵机动力也物理断开，才执行固件恢复与易失 PL 配置。没有发送 ARM、PAN、TLT、HOME、AUTO 或光学控制命令，没有舵机动作。

## 发现并修复的实际问题

ST-Link 只读核验为 Cortex-M4、器件类型 0x413（F405/F407 系列），Flash 容量寄存器为 512 KiB，不读取设备唯一 ID。封装/速度级仍未独立核对。容量寄存器地址依据 [ST 官方 CMSIS F407 头文件](https://github.com/STMicroelectronics/cmsis-device-f4/blob/master/Include/stm32f407xx.h)。

初始 512 KiB 连续读取两次完全一致，SHA-256 `8e000ef6c1c5d59af4bee2e24fb19d4a2e63c0fd0c2f7d735775ad4eac1ab000`，但不匹配此前 d09c81... 的已知候选。检出的非 FF 字节约 1361，无 S1ACK1/S1SYNC 标识，TIM4 CR1/CCER/CCR 均为 0。不能凭此确定是谁更换了固件或原程序的完整用途，不将问题归因于舵机动力。

用本机 ARMCC 5.06u5 编译最新源码的 USART3/S1ACK1/C1_OBSERVATIONS/C1_CLOSED_LOOP 候选，退出 0、零错误、实际一条警告；主机实际控制器、解析器及寄存器测试通过 35,238 项断言。随后只编程首个 16 KiB 扇区，保留未写区域；整片 512 KiB 回读严格等于“新程序 + 原备份剩余字节”。

原始 main.log 在 main.c:88 有 ARMCC #111-D 不可达语句警告：S1ACK1 分支提前 return 后，旧 P0V 遥测代码仍参与编译。现有 build.py 仅匹配小写 warning 或特定 Error 格式，且摘要写死 warnings=0，因此初始摘要及此前进度说明漏报。交付阶段核对原始日志后已更正，[原始警告](../evidence/c1-live-recovery-20261102/arm-main-compiler.txt)与[审计记录](../evidence/c1-live-recovery-20261102/compiler-audit.json)均保留。没有为消除警告临时修改并重新部署固件；构建脚本计数缺陷与条件编译整理仍待修复，不能宣称本次编译零警告。

- 新应用：12,728 字节，SHA-256 `8e9ec97c98c9784d85f3cfe3f26365a1c042b361efcf17dbe06212ae64eb3d26`。
- 完整部署镜像：`bed5e5824a006c8e2bc6ee9e86f6581d4698940fdd0340a46d12ef332817226f`。
- 用当前 ARM 编译的类型布局解析 guardian；8 次采样均 STOPPED/BOOT、CCER=0，毫秒计数正常推进。

初次编译工具默认在 C 盘创建临时目录；已核对并将该次生成的目录迁移至 D 盘，重新显式设置 TEMP/TMP 到本轮 D 盘目录编译。后续使用第二次 D 盘构建产物。没有清理任何其他用户目录。

## FPGA 与图像诊断

恢复前，固定 OV5640 的 8 秒 UDP 探测为零帧。此失败保留为工具执行回执；首个结果文件被后续捕获复用了文件名，不能将重建的回执冒充原始文件。之后捕获工具改用独立标签避免覆盖。

基于本轮先前已布局布线的只观测候选，生成位流（20.892 秒、退出 0、DRC 0 Error），经匹配的 Vivado/hw_server 2024.2 临时 JTAG 配置（14.575 秒、退出 0、startup HIGH）。未写 FPGA Flash。位流 SHA-256：`541cd6129a1646c7fc935da0cdc3a32f54d332631f37002a843495ec4c445510`。

VIO 初始输出全零。人工仅触发诊断查询、日志会话配置和 STOP；QID/session 是本次诊断关联值，不是可靠运动 epoch。该封装的 ARM/位置入口仍在硬件中禁用，PC TX 不作为运动旁路。

恢复后 8 秒收到 206 完整帧、0 不完整、1 启动异常包，206 帧有目标标志；实拍固定相机包含纸上红圆。后续两路观测窗口收到 314 完整帧、0 不完整、1 异常包；108 组同帧 UDP/MCU 的 count/sum/bbox 全部一致。COM14 被动监听识别到 FW15 状态；没有由电脑串口发送运动数据。COM10 打开失败，未据此猜测其用途。

## STOP 与最终状态

实际 FPGA 生成 STOP，收到 QID 关联且 CRC 正确的 ACCEPT/REG 回读，状态 stopped、PWM mask=0；真实 MCU CCER 持续为 0，最终 STOPPED/STOP，测量接收计数在后段稳定。VIO 最终状态 0x50、控制 0x02，FPGA 测量会话已停止。MCU 日志绑定可能保留，不代表运动授权。

这里从始至终没有启用 PWM，因此不是已使能输出的失联关闭时延、实际脉冲波形或机械制动验收。OpenMV 有限诊断已结束，不是持久部署。用户确认的激光与舵机动力断开状态仍保持；没有出光或运动。
