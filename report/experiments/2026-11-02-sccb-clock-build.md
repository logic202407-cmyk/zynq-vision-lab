## 保留的失败与修正

1. 首次构建在创建工程前失败：Vivado 导出的旧 Python 库环境污染本机 Python 3.12，触发 `SRE module mismatch`。改用选定解释器的 `-I` 模式，未改系统环境或依赖版本。
2. 私有分频驱动没有 timescale，首轮 XSim elaboration 拒绝混合时间单位。使用已安装 XSim 支持的 `--timescale 1ns/1ps` 明确缺省单位，未更改私有驱动。
3. 新测试首轮用下降沿计算父周期，复位在低相位释放时多计一个未发生的上升沿，错误报 26。改为统计真实父上升沿并在 NBA 更新后采样；仍严格要求半周期 25、周期 1000 ns，没有放宽期望。最终观察 80 次翻转通过。

这些是工具入口和测试夹具问题，不是已证明的厂商分频逻辑缺陷。各失败日志保留。新的数字仿真不证明模拟波形、复位恢复/撤销、启动相位或 SCCB 电气时序。

## 验收等级与剩余项

即使完整布局布线成功，也只属于离线候选构建证据。物理器件完整标记、100 MHz 参考输入、50/200 MHz 配置输出、PCLK、电平和 I/O 延迟均不得冒充独立实测。两项 FIFO CDC Critical、I/O 时序依据及可靠跨复位 epoch/防回滚提供者仍阻止运动实机验收。

B3 完整综合网表/真实 C 流程仍有中断、没有最终通过回执，本轮没有用 RTL 或新的只观测板级构建代替它。

方法学补充：50 MHz 系统时钟与相机 PCLK 仍触发 TIMING-6/7（无共同主时钟/共同节点）；LUTAR-1×6、PDRC-190、TIMING-18×21 和 XDCC 重复覆盖警告均保留。部分约束来自构建的全量 timing XDC 导出，后续需审查选择性约束持久化和跨域例外的精确范围，不能用全时钟 false path 清空警告。缺失时钟覆盖修复通过不等于方法学或板级签核通过。
