# C1 测量会话及联合采集复测

用户要求在舵机动力和激光供电保持物理断开时，继续核验两摄像头及 FPGA—天空星视觉通信。开始时工作区干净，FPGA DONE=1；只读核对 STM32 完整 Flash 与已批准候选一致，应用 SHA-256 `70a3ad2f0117cb9425d47db79eaad32e0c727ed9936665e2b2bef45599e44812`、STOPPED/BOOT、TIM4 CCER=0。按此前记录为已临时加载的只观测位流关联配套 LTX，实际枚举 1 个 VIO 核。

只观测 VIO 路径的 FPGA 查询进入 AUTH 等待状态；此封装将运动授权与位置命令输入固定禁用，AUTH 不代表 MCU 已使能。首次会话配置后 FPGA 状态 `0x53`、会话未激活；12 秒联合采集 314 个完整视频帧、0 个不完整帧、1 个异常包，无 F1，判定 FAIL。一次被动监听收到 120 条状态、无 V2A/F1，不能据此声称链路通过。

重新以分步上升沿发送只观测查询及测量会话配置，被动监听记录到 1 条 S1SYNC 和 1 条 CRC 正确的 V2A；VIO 之后为 `0xd3`，会话 active 位为 1。调试服务曾以重复命令保护跳过一次释放写入，随后使用不同的实际命令将控制位释放并回读为 `0x02`。首次失败的具体原因未确认。

会话显示 active 后，用户再次运行 OpenMV 45 秒 RAM 脚本；12 秒采集收到 314 个完整帧、1 个不完整帧、1 个异常包，F1 为 0、同帧匹配数为 0，判定 FAIL。原采集脚本进程退出 0，但其 JSON 验收结果为 FAIL，不能把进程退出码当作通过。原脚本使用旧固件 AXF 符号；另建立副本指向已批准固件的 AXF，重测同样为 F1 0、匹配 0、FAIL。副本读取的 MCU 观测字段出现帧数和位置异常，独立重新编译布局对象与旧布局数值一致，尚未定位异常来源；故这些字段以及此前用同一采集方法得出的 MCU OpenMV 坐标和有效帧数，需重新验证，不应作为可靠的本轮同靶或端到端证据。用户现场目视确认 OpenMV 框住红圆，与此分开记录。

发送只观测 STOP 后，VIO 最终状态 `0x50`、控制 `0x02`；此前一次 STOP 的 MCU 应答 CRC 正确，包含 stop/ACCEPT/REG、stopped、PWM mask 0，被动采样 CCER 均为 0。这些结果不证明 PWM 实际波形、带动力停机或机械位置。未发 ARM、运动或激光命令，未写 FPGA Flash、STM32 Flash 或 OpenMV Flash。

尚未解决：active 会话下为何没有 F1、MCU 结构读取与实际数据为何不一致、当前两路测量的逐帧关联。KEY 原因、可靠跨复位 epoch、板级约束、电平、PWM 波形和机械标定仍为运动前阻塞。现场图像、串口原始数据和诊断副本保存于 D 盘，不上传。

末次 STOP 后再次被动监听 120 条状态、无 F1；串口 `S1STAT` 报告 stopped/stop，但现有 SWD 解析器对应的原因字节为 0，二者不一致。该现象可能涉及解析布局、采样对象或其他未确认原因，不归因于接线或硬件故障。TIM4 CCER 的寄存器读取均为 0；串口状态和 SWD 样本目前不能合并为同一安全状态的充分证据。需要先核实运行目标、符号及结构布局，再重新评估本记录及前次的 MCU 解析值。
