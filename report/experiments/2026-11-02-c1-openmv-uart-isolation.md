# C1 OpenMV 串口隔离及 KEY 锁定记录

在[前一检查](2026-11-02-c1-openmv-feedback.md)后，用户确认 OpenMV P4→天空星 PA3 和共地已连接。OpenMV H7 Plus 官方引脚表确认 P4 是 UART3 TX；这只确认功能定义，不能证明线缆电气连续性。

以本机 OpenMV IDE 在 RAM 执行 20 秒隔离脚本，UART3 按 115200、8N1 重复发送协议内的 8 字节无目标帧 `aa ff 00 00 00 00 00 ee`；没有传输运动命令或写相机 Flash。IDE 控制台实际显示 `UART_VALID_PROBE_DONE 9925`，脚本 SHA-256 为 4c1608028ff9723d077f09a162b056fbce5d168a5b14355b25769b0712a7f108；这证明代码完成调用，不能单凭它证明 P4 电压或天空星收到字节。

独立 35 秒被动观测记录 350 行 MCU 状态、172 次安全及 PWM 寄存器采样；OpenMV 接收帧计数始终为 0，F1 为 0，TIM4 CCER 均为 0。首次采样已是状态 FAULT、原因 KEY，无法由本轮采样确定触发时刻。用户表示没有按 WKUP／KEY。随后只读采样 PA0 500 次均为低，故障仍锁定；PA3 在同次采样 500 次均为高。低速采样不等于示波器波形，也不足以证明没有串口脉冲。原始日志、现场图片、备份及脚本保存在 D 盘。

代码中 PA0 高电平会触发 KEY 故障，但本次没有记录到触发瞬间，不能把锁定原因归咎于按键、线缆或串口。安全锁定保持，未进行复位、重新授权、PWM 使能或运动。OpenMV→STM32 实际接收仍未验证，原因待排查。

一次试图并行读取 PA3 时，ST-Link 已被正在运行的采样程序占用，独立枚举未找到可用探针，因而没有得到该次数据；其后单独只读采样成功。不把并发访问失败解释为设备断开，也不把上一轮采样作为本次 UART 波形结果。

本轮所有改动仅为私有诊断脚本和此报告，现有固件、FPGA 位流和相机 Flash 未改变。后续须先核实 KEY 故障成因，再在无动力条件下恢复并验证串口链路；用户仅有万用表，暂不能声称波形通过。
