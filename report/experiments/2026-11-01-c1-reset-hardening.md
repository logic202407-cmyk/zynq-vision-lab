# C1 复位与 QID 边界修复（离线）

基线分支 `work/c1-three-gimbal-vision-20261101`，起点 `0f63e56a1761567a29b961d3db19326a00125416`。开始时工作区干净；再次 fetch 后远端仍为该提交。没有修改 main、原串口透传基线、STM32 核心代码或原有冻结断言。关键文件修改前备份在指定 D 盘证据目录。

## 修复范围

1. 邮箱功能状态与握手同步器改用本域同步释放的复位。
2. 只观测板级封装采用共同断言源、每域一条释放链；相机链接收系统域寄存后的请求，避免跨域复位前组合逻辑和重复同步链扇出。
3. `LOCAL_RESETS=1` 显式复用上游释放链，`generate` 排除不应存在的内部链；默认 0 仍支持两域独立请求清空两端。
4. 测量会话配置复位与该契约一致，UART 整行排队、STOP 优先和三云台独立状态保留。
5. STOP 编号全 1 时故障锁定，不回绕；ARM 前为重新查询和 STOP 各留一个编号。没有关联 STOP ACK 时不宣称确认停止。

接口、复位前提、epoch 方案和复现命令见[说明](../../docs/c1_reset_epoch_hardening.md)。本轮不解除只观测封装的硬件 ARM 禁用，不控制舵机或激光。

## 失败与修正

- 基线复位上下文检出 CDC-7×4、CDC-10×3、CDC-15×689；此前完整厂商板级报告为 CDC-7×4、CDC-10×5、CDC-15×540。这是不同顶层，不能直接拿路径总数互减。
- 只修复邮箱功能复位后仍有 CDC-10×4；把共同请求寄存后又产生 CDC-11×2，暴露重复释放链扇出。
- 第一版本域参数仅用常量选择器绕过内部链，Vivado 仍保留 `ASYNC_REG` 寄存器，报告 CDC-10×2。随后改用 `generate` 在本域模式中排除这两条无用链，没有加 CDC 豁免或全时钟 false path。
- 新复位结构 TB 首轮在时间 0、delta 传播完成前采样 TX，报 `unsolicited UART output`。修正为每个采样边沿后 10 ps 检查，包括初始化阶段；原故障日志保留，原有冻结测试未修改。
- 编号边界试验显示，仅阻止 STOP 回绕仍可能在 ARM 重查消耗最后编号后无法发送关联 STOP，只能等待 MCU 租约。随后增加 ARM 的 STOP 编号预留，并测试仍可用最后编号关闭 PWM。
- 部分 Vivado Tcl 调用超过 MCP 300 秒等待；进程仍运行。只在状态及日志证实完成后记录实际退出码，未把工具等待超时写成设计通过。

## 验证层级与剩余阻塞

本轮只涉及源码、主机 C/RTL 联合仿真、复位上下文 OOC 综合及布局布线。没有生成新位流、JTAG、STM32/OpenMV Flash 写入、设备串口发送或任何动力操作。

原板上只观测位流仍是 SHA-256 `a34a1726d22f9b684da8e84d0450faafa541b5aaceb037f050413e7cc988115c`；它未包含本轮修复。不得把旧板测证据移到新源码上。

仍须完成：完整私有厂商工程的新版本重建与 CDC/时序复审；厂商 FIFO 同步问题；90 无时钟引脚、227 未约束端点、17 输入及 8 输出 I/O 延迟的实际时序依据；J23 实测电平；物理封装/速度级和时钟实测；可靠 epoch 持久化分配/防回滚与区间保护；机械方向/限位及相机标定。数字仿真不能证明模拟毛刺、恢复/撤销或 MTBF。

epoch 仅增加数值保护，**持久化提供者仍为 HARDWARE BLOCKER**。`last_epoch` 不是完整历史，复位清零；旧值和旧区间仍可能复用。诊断 ID、仿真固定数和随机值都不能冒充跨复位唯一性。双通道公共 PWM 使能语义及 500/200 ms 安全边界未变。

结论：本轮修复候选可供离线复核，仍不能申请自主运动实机验收。后续优先关闭完整板级时序/厂商 CDC 与可靠 epoch 提供者，保留激光和舵机动力断开。
