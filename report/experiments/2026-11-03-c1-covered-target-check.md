# C1 遮挡干扰后的 OpenMV 观测

在[LAB 对照检查](2026-11-03-c1-openmv-lab-diagnosis.md)之后，用户确认以白纸遮挡左侧干扰、红圆可见，相机和云台保持不动；舵机与激光动力继续断开。通过 OpenMV IDE 运行 45 秒 RAM 脚本，临时场景阈值 `(5,35,8,40,-10,25)`，脚本 SHA-256 `e2ac7966fa3513e4554e2e05ac762fd958eee7cd266b9131c3d5c578fd116d9a`，未修改相机 Flash 或仓库默认阈值。

实时画面人工观察到红圆被框选，显示 VALID；同次天空星观测快照为 `dx=27, dy=34, valid=1`，软件 PWM=0。另一次 MCU 接收环形缓冲快照找到 32 个 flag=1 帧；该内存快照可能与写入竞争，不是完整数据流统计，不证明跨相机身份或精确机械对准。

随后进行 35 秒被动串口和 SWD 观察，共 172 次采样。前约 12.4 秒中有 62 次读到 OpenMV 观测有效，观测帧计数由 10312 增至 10889；45 秒 RAM 程序结束后，观测过期并变为无效。所有安全状态采样为 STOPPED/BOOT、TIM4 CCER=0；这些是离散寄存器采样，不是 PWM 波形测量。

该 35 秒监视脚本的**总退出码为 1 / FAIL**：COM15 未收到任何 FPGA 透传状态或 F1，因此不能把本次有效 OpenMV 观测误报为完整 FPGA—天空星链路通过。JTAG 未枚举、FPGA UDP 未出帧、F1 和两摄像头关联仍待核验；KEY 的原始触发原因、epoch、板级约束和机械标定仍未解决。

本轮没有烧录、复位、ARM、真实 PWM 使能、云台运动或光学控制。实时截图及 UART 原始数据留在 D 盘；[脱敏采样与结果](../evidence/c1-covered-target-20261103/)供复核。下一步先通过 JTAG USB 的拔插与设备列表变化确认代码 43 设备是否为下载器，再恢复现有 FPGA 诊断链路。
