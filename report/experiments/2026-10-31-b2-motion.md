# B2 autonomous motion: offline candidate acceptance

Base: `work/b2-uart-cosim-20261031`, commit `6aca9ac025dbef7af8b02218c1e9f50bdd5cf993`.
The current XSim/real-C regression passed 22 coupled scenarios and 26 C safety
cases. Final routed functional smoke passed with exit0. No hardware operation is authorized.

## Scope

Implemented S1ACK1 as an opt-in STM32 response extension and an independent
Verilog-2001 `zynq_motion_s1` controller. Existing transparent bridge, diagnostic
controller, UART TX/RX, safety supervisor and tracking core remain unchanged.
See [implementation and reproduction](../../docs/zynq_skystar_motion_implementation.md).
Both PWM channels retain the existing common enable semantics. PAN/TLT update
only the selected target; home updates both. No angle or waveform measurement is claimed.

## Verification boundary

The coupled harness runs actual XSim UART pins and the actual STM32 console,
USART ISR, safety, tracking and board driver C code against a register model.
It does not replace command parsing with a Python replica. The independent host
serializer models 115200/8N1 and drives RX bits; only named fault tests mutate replies.
The model does not establish all interrupt preemption races, timer shadow timing,
physical waveform validity, board clock identity or electrical safety.

## Failures retained and corrected

An early ACK metadata parser rejected the short protected heartbeat; the minimum
body length was corrected without modifying the S1 safety protocol. Long leading-zero
sequence numbers accepted by v15 remain accepted and are echoed canonically.
A first RTL formatter caused excessive combinational resource use; bounded sequential
formatting and numeric accumulation replaced it without changing wire expectations.

Crucially, an earlier RTL/C passing candidate failed the independently decoded
functional-netlist smoke: TX remained low through the stop bit. Timing/route PASS
was therefore NOT accepted as functional proof. Explicit registered TX data prefetch
was added. The failed netlist and logs remain in private D-drive evidence. Final
acceptance requires the unchanged 45-byte golden query and stop-bit assertions.

## Hardware gates

Actual FPGA input clock, package/speed grade, control pins, reset/input conditioning,
unique cross-reset epoch provisioning, J23 voltage and actual STM32 Flash identity
remain unverified. OOC checks use candidate xc7z100ffg900-2 / 100MHz only, no pin
assignment or IO delay signoff. No bitstream, JTAG, flashing, COM port access,
servo power change or physical motion was performed. Stopped PWM is not power removal.

## Next boundary

Offline tests cannot authorize a hardware test. Review the report, integration
constraints and independent power cutoff before any separately approved hardware step.

No all-bit reset sweep, baud tolerance sweep, exhaustive interrupt race test,

are RTL/C coupled simulation. Earlier tool/session failures and bad netlists are
not counted as passing evidence. The Vivado plugin's long-call timeout and a
separate session crash required fresh offline batch runs; no claim of complete
plugin reliability is made.

## Reproducibility timing issue

The first final routed-netlist run printed `MOTION_NETLIST_PASS` after259seconds,
but its parent runner had a240-second timeout and returned1. It is NOT counted as
a zero-exit acceptance. Its log is retained; the same compiled snapshot is rerun
with600seconds, without changing the testbench or expectations. The general
netlist runner now uses600seconds as well. This changes only execution budget.
